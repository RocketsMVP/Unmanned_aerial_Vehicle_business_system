# Unmanned_aerial_Vehicle_business_system

## 项目简介

`Unmanned_aerial_Vehicle_business_system` 面向重庆高速公路全域低空无人机 AI 应急处置场景，聚焦交通事故、边坡滑坡、路面塌陷、隧道险情、危险品泄漏等突发事件，目标是构建一套集“快速响应、精准研判、协同联动、复盘优化”于一体的业务系统。

本仓库当前主要承载该课题的后端基础平台与模块化能力建设，包括系统管理、权限控制、文档管理、字典管理、基础存储与接口底座；无人机调度、AI 态势识别、GIS 指挥调度等能力对应的是项目设计目标与后续迭代方向。

## 课题背景

重庆高速公路具有“山地地形复杂、桥隧密集、气候多变、交通流量不均”等特点，传统应急处置面临以下挑战：

- 事故 / 险情发现滞后，偏远山区、长下坡、隧道等场景难以及时感知
- 现场态势获取困难，传统手段难以快速形成全局视图
- 多部门资源协同效率低，调度链路长、信息不对称
- 现场风险研判不足，二次事故与危险扩散难以及时预警

低空无人机具备机动灵活、快速抵达、全景覆盖等优势；结合 AI 态势分析、风险识别和资源调度能力，可为山区高速应急管理提供更加高效、精准、安全的数字化支撑。

## 设计目标

本项目围绕以下四类核心能力进行设计：

### 1. 应急快速响应

- 支持多渠道险情上报与统一事件编号
- 支持就近无人机快速调度与任务分配
- 支持应急作业路径规划与复杂环境下飞行适配
- 目标提升事故发现速度与现场到达效率

### 2. AI 态势智能感知

- 识别交通事故、道路险情、隧道险情、危险品泄漏等事件类型
- 研判人员、车辆、道路阻断与现场风险状态
- 自动生成态势报告，为指挥决策提供依据

### 3. 多部门协同处置

- 实现交警、消防、医疗、养护等资源可视化调度
- 提供最优路径规划、指令推送、进度反馈与远程指挥支持
- 支持警戒区划定与交通管控联动

### 4. 处置过程管理与复盘优化

- 记录处置全过程关键节点、指令与资源调用信息
- 支持现场数据持续更新与任务跟踪
- 自动生成复盘报告，为后续流程优化提供数据支撑

## 设计目标指标

以下指标来自课题任务书，是本系统的设计目标，不代表当前仓库代码已全部实现：

- 无人机应急部署启动时间不超过 3 分钟
- 抵达事发区域时间控制在 15 分钟内
- AI 态势识别响应时间目标不超过 3 秒
- 资源调度与路径规划响应时间目标不超过 2 秒
- 险情类型识别准确率目标不低于 93%
- 被困人员识别准确率目标不低于 90%

## 当前仓库已实现内容

当前仓库更偏向后端平台基础能力，已落地的内容包括：

- **FastAPI 异步服务入口**：基于 `main.py` 和 `core/http.py` 启动 API 服务
- **模块化装载机制**：通过 `system.addons-path: core/app` 自动加载业务模块
- **系统管理能力**：用户、角色、菜单、接口、JWT、Casbin 鉴权与初始化数据
- **文档管理能力**：文件上传、文件渲染、分片上传、断点续传、文档记录
- **字典管理能力**：基础字典数据维护
- **数据库迁移能力**：基于 Alembic 管理表结构
- **缓存与存储抽象**：支持 Redis，支持本地存储与 MinIO 切换
- **文档处理依赖基础**：已集成 PDF / Word / Excel / PPT 等文档解析相关依赖
- **仓库形态说明**：当前代码以后端 API 为主，前端 GIS 展示与移动端能力尚未在本仓库中落地

## 技术栈（当前代码）

- **语言**：Python 3.10+
- **Web 框架**：FastAPI、Uvicorn
- **数据库**：MySQL（主路径）、SQLAlchemy、Alembic
- **缓存**：Redis
- **对象存储**：本地存储 / MinIO
- **权限认证**：JWT、Casbin
- **文档处理**：`python-docx`、`pypdf`、`pdfminer.six`、`mammoth`、`openpyxl`、`python-pptx` 等
- **运行特性**：Windows 下自动回退到 `asyncio`，非 Windows 优先使用 `uvloop`

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置环境

根据实际环境修改 `config.yaml`，重点关注：

- 数据库连接
- Redis 连接
- 存储方式（本地 / MinIO）
- 系统监听地址与端口

> 建议通过环境变量覆盖敏感配置，不要将真实账号、密码和密钥直接提交到公开仓库。

### 3. 启动服务

```bash
python main.py
```

### 4. 验证服务

- 健康检查：`/ping`
- 接口文档：`/docs`
